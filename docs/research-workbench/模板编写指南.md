# 科研工作台模板编写指南

> 面向模板作者（把科研流程固化为可执行、可复现、可中断续跑的 DAG）。
> 代码参考：`packages/server/src/modules/research/workflows/`（模板注册表与契约），
> 已有范例：`literature-review`、`paper-translate`、`overnight-research`、`figure-drawing`（同文件 `templates.ts`）。

## 1. 模板是什么

一个「模板」是一份节点 DAG 定义（节点 + 边 + 入口），由引擎校验后按三份注册表分发：

| 节点类型 | 谁执行 | 是否建聊天会话 | 说明 |
| --- | --- | --- | --- |
| `agent` | 引擎聊天运行 | ✅ | 智能节点，提示词按模板提供，可绑定 skill |
| `script` | 确定性执行器（真实 Node 子进程） | ❌ | 机械节点，stdin 注入、stdout 即输出 |
| `validate` | 执行器（当前阶段未配置，报错明示） | ❌ | 校验类占位 |
| `render` | 执行器（当前阶段未配置，报错明示） | ❌ | 渲染类占位 |

**确定性节点契约（五字段）**：`title`、`input`、`orchestration`、`runtime: 'node'`、`code`（脚本源码字符串）。agent 节点字段：`{title, input, orchestration, skills?, prompt}`——agent 字段**全有或全无**。

## 2. 注册模板（三步）

1. 在 `templates.ts` 用 `scriptTemplateNode(...)` / `agentTemplateNode(...)` 定义节点，`defineTemplateDefinition(...)` 定义模板（入口 `entry` + 节点 `nodes` + 边 `edges`）。
2. 模板注册表会自动纳入 `template-contract.ts` 的校验：单入口、全节点可达、script 五字段、agent 字段完整性。
3. 写测试：模板契约测试（验证形状）+ 模板级 e2e（见第 6 节）。

## 3. 节点输入协议（最容易踩的坑）

引擎把上游结果包装后作为节点 stdin 输入（`manager.ts buildNodeUserMessage`），脚本收到的输入会包含这些**包装段**：

```text
[Workflow upstream results]
[Upstream: <上游节点标题>]
<上游输出一>
[Upstream: <上游节点标题>]
<上游输出二>
[Current task]
<当前节点任务提示>
```

### 3.1 脚本必须剥离包装行

- **简单解析**（入口/报告节点）：先调 `stripEngineWrapperLines()` 剥掉 `[Workflow upstream results]`/`[Upstream: ...]`/`[Current task]`/占位 task 行（常量 `ENGINE_WRAPPER_HELPERS` 已内插到每个脚本，直接用）；`parseJsonPayload()` 先整体 `JSON.parse`，失败再取首 `{` 到末 `}` 子串解析（兼容"包装行 + JSON 混排"）。
- **需要按上游区分**（菱形 join 节点）：不要先剥壳——用 `splitUpstreamSections()` 按 `[Upstream: ...]` 头分节，节内内容对应各上游节点的输出，再逐节处理。

> 反例教训：T2.2 首版 paper-translate 三个脚本假设 stdin 是裸路径/裸 JSON，真实引擎跑不通；lit-review 报告脚本只剥了一类包装行，导致报告正文被污染。所有脚本都应按上述规则处理。

### 3.2 输出契约

- script 节点 stdout 为节点输出（引擎侧有 **5MB/流 输出上限**，超限会终止并结构化报错——大批量任务注意分批）。超限失败是 loud fail，不静默。
- 产物落盘：引擎把 run 工作区作为 cwd 传给脚本；绝对路径产物（如 `morning-report.html`、`figure.svg`）写入任务要求的目录（输入中由 intake 节点校验过的绝对路径）。

## 4. DAG 形态

- **线性**：入口 → 顺序节点 → 报告节点（文献综述）。
- **菱形 join**：入口并行接两个处理节点，再汇聚（过夜科研、绘图）；汇聚节点用 `splitUpstreamSections` 分节。
- 不需要动态 fan-out：批处理由入口脚本读取队列文件分好批，各批在脚本内/agent 提示词约束下处理。

## 5. Agent 节点与 skill 绑定

```js
agentTemplateNode({
  title: '图绘制智能体',
  prompt: `...输出单个 ```svg 围栏...`,
  skills: ['scientific-figure-style'],
})
```

- `skills` 引用的技能必须已装载（skillpack 服务安装到 Agent skill 目录）；未装载时 preflight 会 409 拒跑（设计如此，templates 内应给出明确错误文案）。
- prompt 中约束输出格式（如"单个 ```svg 围栏"），下游 script 节点按该格式抽取；聚合/渲染脚本对 agent 输出格式做**容错解析**（bullet/围栏/多段），并容忍缺行（计 missing 而非静默）。

## 6. 端到端测试模式（必须）

模板级 e2e 是验收标配（范例：`tests/server/research-workflow-templates-e2e.test.ts`、`research-overnight-research-e2e.test.ts`、`research-figure-drawing-e2e.test.ts`）：

1. **mock 聊天层**：替换 `workflow-runtime.runWorkflowAndWait` 为按 `[Current task]` 提示文本映射输出的 canned 队列，并把输出按 session_id 塞回 `sessionOutputs`（供 `lastAssistantOutput` 读回）。
2. **真实执行确定性节点**：`runWorkflowDeterministicNode` **不 mock**，转发真实 `executor.executeWorkflowDeterministicNode`——script 节点以真实 `node -e` 子进程跑模板脚本。
3. **外部二进制 stub**：spawn 的 pdf2zh/python-pptx/rag sidecar 用 `node` 包装脚本 stub（argv/stdin 契约与真实工具一致，经 `PAPER_TRANSLATE_PDF2ZH_BIN`/`RESEARCH_FIGURE_PPTX_PYTHON` 环境变量注入真实路径）。
4. 断言：`run.status === 'completed'`、每个节点行已完成、产物文件真实落盘且内容无引擎包装行泄漏。

## 7. sidecar 约定（外部工具）

| 环境变量 | 用途 | 结算方式 |
| --- | --- | --- |
| `PAPER_TRANSLATE_PDF2ZH_BIN` | pdf2zh（1.x/2.x/next 经 node 包装脚本统一 argv：`-i <pdf> -o <outDir> -s openai -lo <lang>`） | 结构化 argv、`shell:false`、密钥只经环境变量 |
| `RESEARCH_FIGURE_PPTX_PYTHON` | python-pptx sidecar（SVG 子集映射为可编辑形状） | 未配置时优雅降级（`pptxExported:false` + reason，run 仍 completed） |
| `RAG_SIDECAR_BIN` / `RAG_SIDECAR_PYTHON` | paper-qa sidecar（stdin `{action:index|ask,...}` JSON → stdout 最后一个 JSON） | 与模板链解耦，见 `docs/research-workbench/T4.1-rag-spike.md` |
| `TECTONIC_BIN` | LaTeX 编译器 | 见 `docs/research-workbench/T3.3-latex-spike.md` |

要点：**版本适配收敛在包装层**，模板/服务端只依赖一个稳定 argv/stdin 契约；spawn 用参数数组（绝不拼 shell 字符串）；密钥不进 argv/log/DB。

## 8. 从零写一个新模板的 checklist

1. `templates.ts` 定义节点与模板；`scriptTemplateNode`/`agentTemplateNode` 辅助函数保证五字段/agent 契约。
2. 每个 script 节点内部：先处理引擎包装行（3.1 规则）；解析入参失败要清晰地"失败 + stderr 原因"，不静默。
3. 产物节点：输出 JSON 摘要 `{format, title, reportPath, bytes, stats...}`，便于引擎放 output_json。
4. 添加模板契约测试（`research-workflow-templates.test.ts`：形状/拓扑/round-trip）+ 模板级 e2e（第 6 节）。
5. 跑验证：`npx vitest run tests/server/research-*`；`node scripts/server-module-boundaries.mjs`；`npx tsc --noEmit -p packages/server/tsconfig.json`。
6. 若模板只动 `modules/research/**` 与 `tests/server/research-*`：**零基座改动，无需登记 BASE-CHANGES-REGISTRY**；动了基座文件则必须登记（BC 表）。
7. 提交：`feat(research): ...`；不 push，等审查。

## 9. 常见错误自查

- ❌ 脚本假设裸输入 → ✅ 先 `stripEngineWrapperLines`/`splitUpstreamSections`。
- ❌ 报告正文出现 `[Upstream:`/`[Current task]` → ✅ 聚合/报告节点剥离后再渲染。
- ❌ stdout 无限输出（内存/上限）→ ✅ 大量数据分批或只输出摘要 JSON。
- ❌ 未知节点类型放行 → ✅ 只注册已知类型；引擎对未知类型显式拒绝。
- ❌ agent 输出格式假设严格 → ✅ 聚合脚本容错解析 + 缺行计 missing。
- ❌ sidecar 路径硬编码 → ✅ 环境变量注入 + 未配置明确降级。
