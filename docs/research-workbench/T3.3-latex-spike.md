# T3.3 LaTeX Spike 报告：tectonic 环境验证与编译链路

- 分支：`feature/p3-T3-latex`（基线 main abf1275）；日期：2026-09-02
- 方法：本机探测 tectonic 安装形态、跑通 stub 与真实编译两条测试路径，并核对 compile queue 与 BC-5 引擎生命周期标准的一致性。
- 结论速览：**真实 tectonic 可用但不在 PATH**，通过 `TECTONIC_BIN` 显式指认即可端到端出 PDF；无 tectonic 的环境（CI）由 stub tectonic（node:child_process mock 写出 PDF 字节）承载主覆盖，真实编译为 opt-in 冒烟。

---

## 1. 环境结论（本机实测）

| 项 | 结果 |
| --- | --- |
| `tectonic --version`（PATH） | 不可用（`where tectonic` 找不到） |
| 实际安装位置 | `C:\Users\rikey123\tectonic\tectonic.exe`，版本 **Tectonic 0.17.0** |
| TeX bundle 缓存 | `%LOCALAPPDATA%\TectonicProject\Tectonic\cache\bundles`（default_bundle_v33 已下载）——首次真实编译不再联网 |
| Windows 安装形态 | 单文件 exe；`.bat/.cmd` shim 不可用于 `spawn(…, {shell:false})`（Node ≥18.20 拒绝批文件），解析器只认 `.exe` |

### 获取/配置方式（交付环境通用）

1. 安装（任选其一）：
   - GitHub Releases 下载对应平台压缩包，解压出 `tectonic(.exe)` 后放入任意目录（本机即此形态）；
   - `scoop install tectonic` / `winget install TectonicTypesetting.Tectonic` / `cargo install tectonic`（装入 PATH 后无需第 2 步）。
2. 配置（二进制不在 PATH 时）：为服务端进程设置环境变量
   ```bash
   TECTONIC_BIN=C:\Users\rikey123\tectonic\tectonic.exe
   ```
   - `TECTONIC_BIN` 是权威约定：`resolveTectonicBin()`（`packages/server/src/modules/research/latex/tectonic.ts`）先读 `TECTONIC_BIN`（存在性校验），再回退扫描 PATH（Windows 仅接受 `.exe`，POSIX 扫 `tectonic`）。
   - 未解析到引擎时 `POST …/compile` 返回 **503 `engine_unavailable`**，前端 `ResearchLatexView` 显示 `research.latex.engineUnavailable` 文案，不会崩溃。
3. 相关环境变量汇总：
   - `TECTONIC_BIN`：引擎二进制路径（优先于 PATH）。
   - `HERMES_LATEX_COMPILE_TIMEOUT_MS`：单次编译超时（默认 180000ms；超时按 BC-5 规则杀整棵进程树并落 `failed`）。
   - `HERMES_LATEX_SMOKE=1`：开启真实编译冒烟测试（见下）。

## 2. 测试双轨制

| 路径 | 测试 | 触发条件 | 覆盖 |
| --- | --- | --- | --- |
| stub tectonic | `tests/server/research-latex.test.ts` | 无条件（CI 主覆盖） | mock `node:child_process.spawn`，行为钩子写 PDF 字节后 `close(0)`；覆盖 CRUD、503、202+轮询、错误解析、409 并发、超时终止、模板论文编译 |
| 真实 tectonic | `tests/server/research-latex-real-compile.test.ts` | `HERMES_LATEX_SMOKE=1` 且能解析到引擎，否则 `describe.skipIf` 整体跳过（CI 无 tectonic 不误伤） | 仓库自带模板论文 `templates/default-paper.tex` → 真实 PDF（校验 `%PDF-` 头），240s 超时（首次 bundle 下载可能较慢，本机缓存已热） |

本机真实编译命令：

```bash
HERMES_LATEX_SMOKE=1 TECTONIC_BIN=/c/Users/rikey123/tectonic/tectonic.exe \
  npx vitest run tests/server/research-latex-real-compile.test.ts
```

## 3. 验收链路核对

1. **模板论文编译出 PDF**：`packages/server/src/modules/research/latex/templates/default-paper.tex` 为权威模板（只用标准 article 类，默认 bundle 即可编译）；无 source 建档时由 `latex-service.createLatexDocument` 播种该模板；stub 与真实测试均编译它并断言 PDF 字节。
2. **错误面板定位**：`parseTectonicErrors` 支持 rustc 摘要（`file:line: msg`）、`--> file:line:col`、经典 TeX `! msg` + `l.N`（含 `(./file.tex` 括号 token 跟踪当前文件），有专项测试；前端错误面板点击 → `focusError` 在 textarea 中选中对应逻辑行并滚动（`ResearchLatexView.vue`，含客户端测试断言 selectionStart/End）。
3. **实时预览**：编译 POST 返回 `queued` → 视图 1s 链式 `setTimeout` 轮询 latest → `completed` 后拉取 `/compilations/:id/pdf`（鉴权 blob）刷新 `PdfFilePreview`；`queued/running` 期间按钮防重入（`compiling` 状态 + 服务端 409 双保险）。
4. **队列安全**：进程内串行队列（`compile-queue.ts`）保证并发=1；单文档 queued/running 期间拒绝重复入队（409）；陈旧 active（>30min）不锁死；超时按 BC-5 标准经 `studio/public/process-tree` 的 `killOwnedProcessTree`（Windows `taskkill /T /F`，POSIX `SIGKILL`）清理整棵进程树，Research 只依赖 Studio public facade，符合模块边界矩阵。
